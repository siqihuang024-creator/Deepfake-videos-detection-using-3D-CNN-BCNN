阶段 A 实验协议

3D-CNN 特征提取器的有监督预训练——每一步的规格、判定标准，以及它所依据的文献。

Stage A · Feature extractor pre-training CelebDFv3 (Celeb-DF++) · DFD 2026-09-04
0

交付物与判定原则

阶段 A 唯一的产出是一个冻结后交给阶段 B 的特征提取器。分类头（DeterministicHead，feature_dim → 512 → 1）训完即丢弃。

因此判定标准不是 AUROC 高，而是「AUROC 高，且这个高不是来自数据集捷径」。头可以重训，提取器没学到的东西阶段 B 永远拿不回来——它是被冻结带走的。

前一轮整帧实验就是败在这里：CelebDFv3 拿到 0.819，但只看画布填充比例的零学习对照是 0.828。网络把容量全花在捷径上，真正的伪造特征一点没学。本协议的第 3 步就是为了防止这件事重演。
1

数据划分

三条规则：

  1. 身份是划分的最小单位，一个人的全部视频只进一个划分。
  2. 一条伪造视频进入某划分的条件是被篡改者与人脸提供者同属该划分，否则剔除。train↔val、train↔test、val↔test 三组全部互斥。
  3. 59 位名人与 300 个 YouTube 身份分开分层——后者没有任何派生假视频，混在一起洗牌会稀释名额。

名人按 60/20/20、YouTube 身份按 70/15/15，种子 42。相比现行划分，训练假视频只减少 7%，而验证集的两类兼具身份从 7 涨到 12。DFD 不设测试集：28 位演员切出的 4 人测试集置信区间宽达 ±0.3，不具备分辨力。

依据 规则 1–2 照搬 FaceForensics++（Rössler et al., ICCV 2019）：其官方 dataset/splits/*.json 存的是身份对而非视频编号（360 / 70 / 70 对），实测三组两两重叠全为 0，比例 72:14:14。为什么必须如此见 Dong et al., Implicit Identity Leakage, CVPR 2023。规则 3 是针对本数据集结构的推导，无直接文献。

3

捷径对照门禁 · 训练前必做

在写下第一个训练命令之前，用不含任何伪造信息的单个标量去给验证集排序，看能得到多少 AUROC。三个必测：

  • 重采样系数 256 / (1.3 × 人脸框宽)
  • 原始画幅（宽、高、长宽比）——裁剪后应当已经失效
  • 人脸框像素宽

放行条件：三个都落在 0.5 ± 身份级置信区间内。任何一个显著偏离，先修预处理，不许开始训练。

已知必须复查的两处：整帧流程下「画布填充比例」拿到 0.828；未配对的 300 条 Real_YouTube 中有 220 条落在名人视频从不使用的分辨率上，判真精度 100%。这两条捷径按理都会被「裁剪 + 固定 256×256」消灭，但必须实测确认，不能推断。

依据 这类「用输入的一个片段去预测标签」的检验在 NLP 有正式名称 partial-input baseline：Poliak et al., *SEM 2018（只看假设句在 SNLI 拿到 71%，随机为 33%）与 Gururangan et al., NAACL 2018。deepfake 领域的同类发现见 Smeu et al., CVPR 2025——两个最常用的音视频数据集中，假视频开头的一小段静音「based on this feature alone, we can separate the real and fake samples almost perfectly」。

采样

clip_length8 帧，连续
train_clip_strides[1, 2]，每次随机选一个
eval_clips_per_video8，eval_clip_stride: 2
train_balance_keys[dataset, class_name]，每 epoch 真假等量
horizontal_flip0.5

必须声明的协议偏离：DeepfakeBench 取 32 帧独立抽样，我们取 8 段 × 8 帧连续——时序连续性正是本文的贡献所在，无法取消。评分侧一致：每条视频输出一个分数（clip logits 取平均）。

配对不需要额外构造：核对结果显示六个（数据集, 划分）单元中，每条假视频的源真视频都在同一划分内，覆盖率 100%——这是身份划分的自动结果，因为假视频与其源真视频身份相同。

依据 Yermakov et al., WACV 2026：「training on paired real-fake data from the same source video is essential for mitigating shortcut learning」。注意其配对用于训练集构造，不涉及评估。
5

训练

两次独立运行，每个数据集一个。不得合并训练——合并后的提取器会让 2×2 矩阵的跨库格失效。

architecture3d，conv_channels [16, 24, 32]，spatial_kernel 5，temporal_kernel 3
feature_dim15 488（32 × 22 × 22，AdaptiveAvgPool2d(22) 使其与输入尺寸无关）
headDeterministicHead：15488 → 512 → 1，dropout 0.2。训完丢弃
objectiveBCE-with-logits，无 KL 项
optimiserlr 1e-4，gradient_clip_norm 5.0，lr_gamma 0.95 每 epoch
epochs60，early_stopping_patience 8
selection_metricmacro_dataset_auroc，min_improvement 0.002
seed42

缓存人脸框与 landmarks 之后 GPU 才是瓶颈，届时 --batch-size 可以从 1 上调。运行方式一律 nohup python -u …——VS Code 终端重连会发送 Ctrl+C 杀掉任务。

评估

  • 评估集剔掉 Real_YouTube（val 45 条、test 45 条）。它们没有派生假视频，且带 100% 精度的分辨率标记；剔除后评估集恰好成为严格一一对应的配对结构（val 121 对、test 125 对）。训练集保留——多 60% 的真视频，而其危险来源已被裁剪消灭（须经第 3 步确认）。
  • 主指标：video-level AUROC，每条视频由 8 段 clip 的 logit 取平均得到一个分数。
  • 置信区间：在源片段与身份两级做聚类 bootstrap。视频级 bootstrap 是错的——test 看似 5 433 条假视频，实际只来自 125 段源片段，同一段画面被 22 种方法改了约 43 遍，高度相关。
  • 参照系：Celeb-DF++ 的 GF-eval 平均 video-level AUC 为 72.1%，最佳方法 84.4%。协议不同，只作量级参考，不可直接比较。
依据 聚类数据下的 ROC 估计：Obuchowski, Biometrics 53(2):567–578, 1997。同一测试集上比较两个模型：DeLong et al., Biometrics 44(3):837–845, 1988。AUROC 标准误的闭式解：Hanley & McNeil, Radiology 143(1):29–36, 1982。评估集剔除未配对真视频一项，无直接文献先例，理由由第 3 步的实测支撑。
7

成功判据

三条同时满足，才允许把提取器交给阶段 B：

  1. 验证 AUROC 超过第 3 步的每一个捷径对照，且超出量大于身份级置信区间。
  2. 训练损失跌破 ln 2 = 0.6931。这是本项目的经验判据：十次 CelebDFv3 运行中，v9 是第一个做到的，也是最好的一个；DFD 从未做到，其损失停在 0.673–0.920。
  3. 提取器输出的标准差在训练过程中不塌缩（v6 曾从 0.174 衰减到 0.099，v9 保持在 0.515 平稳）。

任一条不满足，问题出在预处理或数据，不要靠调超参去补——我们已经证明这条路走不通：在 12 个测试身份上可分辨的差异约为 ±0.05，而 v7 / v8 / v10 的全部改动都落在这个范围内。

—

明确不在本协议范围内Stage A 之外

  • 阶段 B：冻结提取器 + 贝叶斯均值场头、仅用真视频的单类训练
  • 身份级 k 折交叉验证（属于最终报数阶段，非开发阶段）
  • 配对评估（源片段内比较）——统计上成立但领域内无先例，只进补充材料
  • Celeb-DF++ 官方 GF-eval（换泛化轴，作为可比性对照单独进行）
  • TalkingFace 驱动音频的互斥约束——先解析入 manifest 并测量污染程度，暂不强制
